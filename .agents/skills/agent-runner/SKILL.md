# AgentRunner local handoff

Use this skill for a local machine task whose commands and completion criteria can be prepared before execution. Keep research, design, interpretation, and decisions with Codex. On Windows, prefer the installed executable at `$env:LOCALAPPDATA\Programs\AgentRunner\runner.exe`; invoke it in PowerShell with `& (Join-Path $env:LOCALAPPDATA 'Programs\AgentRunner\runner.exe')`. If it is absent, use `python -m agentrunner` only when that Python package is available. Do not assume the current project contains AgentRunner. A short command can run directly; an obviously long command uses `run`; uncertain duration uses `exec --adaptive`; a dependent or parallel DAG uses `submit workflow.yaml`.

Before submission, establish the command or Workflow, working directory, success and failure criteria, expected artifacts, required resources, observation points, timeout and cleanup/finalizers where relevant. Check inputs and executable paths. Do not submit paid remote work or an irreversible external action without the authorization that action itself requires. Pass only required environment names with `--pass-env` or the Workflow field; do not put secrets into the Workflow, command arguments, or callback text.

For a callback to the current Codex chat, provide its actual thread UUID with `--callback-thread`. If the thread UUID is unavailable, say that callback delivery is not configured for this Job; do not guess an ID. For an installed Windows background Job, open `runner desktop` before submission. If the command tool isolates GUI processes from the user's desktop, use its approved interactive/unsandboxed execution mode for this window launch (in Codex `exec_command`, `sandbox_permissions: "require_escalated"`); do not infer visibility from a running process. Submission also requests Service and desktop startup, but this does not prove the window is visible. Report any `surface_warnings` and any unverified visibility honestly. The callback Skill checks local Job identity and uses atomic claim/ack to suppress repeated follow-up; callback delivery and user-facing replies are still not exactly once.

Read the single submission response. On `ACCEPTED` or `PROMOTED_TO_BACKGROUND`, report the Job ID, handoff state, and how the user can inspect it, then end this turn. Do not start a status, log, file, process, SSH, or sleep-and-query loop. Runner owns mechanical execution; closing the UI or ending the Codex turn does not cancel it. On `COMPLETED`, use the returned exit status and perform only the remaining requested interpretation. On rejection or `UNKNOWN_SUBMISSION`, correct a clear validation error or inspect the identified Job once before deciding whether a new submission is safe; never blindly submit the same side-effecting task again.

After handoff, respond to a callback or a user-requested one-time diagnosis. A user query does not transfer Job ownership to Codex. For a Workflow whose supervisor is lost, use `reconcile` and the documented `UNKNOWN` resolution commands; never infer a step's outcome from missing output or retry an unconfirmed side effect.

## Goal-mode handoff boundary

Ending a turn does not prove that an active Desktop goal has stopped automatic continuation. For this integration, acceptance requires Codex to remain idle until the handed-off Job's callback or a new human instruction. Do not treat an automatic goal continuation as permission to check the Job, develop unrelated changes, run additional acceptance probes, or submit another Job while that handoff is pending. Arrange dependent machine work inside the original script or Workflow before submission.

If goal mode is active, explain the scheduling limitation before handoff. Only pause a goal with explicit human authorization; authorization for one probe does not authorize all future pauses. When the installed Runner supports it, use `run --pause-goal --callback-thread UUID` or `submit WORKFLOW --pause-goal --callback-thread UUID` after that authorization. The experimental local protocol preserves the goal and budget, and records pause ownership against this Job. It is unavailable for `exec`; choose a detached `run` for an authorized goal handoff. A returned `goal_handoff.status=PAUSED` confirms suspension. Any other result does not prove an active goal stopped; report it without resubmitting the already accepted Job. Do not clear the goal, mark unfinished work complete or blocked, edit Codex state files, or claim a Skill enforces a scheduler stop. A callback for another Job does not release this handoff boundary. Report turn-ending, goal suspension, and resumed work as separate facts.

See the [public README](https://github.com/Tao-Mei/AgentRunner) and `runner --help` for supported commands and recovery limits.
